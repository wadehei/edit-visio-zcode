# 移动端页面可视化装修平台 —— 总体方案

> 版本:v0.1(2026-10-09)
> 项目代号:Visio 装修平台(仓库 `edit-visio-zcode`)

## 1. 背景与目标

运营/业务人员需要频繁产出移动端 H5 活动页、店铺首页,传统做法依赖前端排期开发。本平台提供**拖拽式可视化装修能力**:左侧选物料、中间手机画布实时预览、右侧改属性,最后保存并发布,让非技术人员独立完成页面搭建。

**MVP 目标(本期):**

- 页面管理:新建(空白/模板)、编辑、复制、重命名、删除、导出/导入 JSON
- 可视化编辑:物料拖入画布、拖拽排序、选中、上移/下移/复制/删除、快捷键(撤销/重做/删除)
- 属性配置:Schema 驱动的动态表单(文本/数字/开关/下拉/颜色/滑杆/图片/列表)
- 实时预览:编辑与预览共用同一渲染引擎
- 数据持久化:localStorage 本地存储(无后端依赖,可随时替换为 API)

## 2. 术语表

| 术语 | 含义 |
| --- | --- |
| 页面(Page) | 一次装修的产物,对应一份 `PageSchema` JSON |
| 物料(Material) | 可拖入画布的最小组件单元,如轮播图、商品卡片 |
| 画布(Canvas) | 中间 375px 宽的手机模拟区,所见即所得 |
| Schema | 页面/组件的 JSON 数据描述,渲染的唯一数据源 |
| 物料描述符(MaterialDefinition) | 物料的元信息:类型、名称、图标、默认属性、属性表单 Schema、渲染组件 |

## 3. 使用流程

```
页面列表 ──新建(空白/模板)──> 编辑器(/editor/:id)
                                  │  拖拽/点击物料 → 画布
                                  │  选中组件 → 右侧改属性
                                  │  撤销/重做/快捷键
                                  ├─ 预览(/preview/:id,新标签页)
                                  └─ 自动保存 + 手动保存(导出/导入 JSON)
```

## 5. 技术选型

| 领域 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Vue 3.5(组合式 API + `<script setup>`) | 装修类中后台生态成熟;响应式系统对属性面板双向绑定友好 |
| 语言 | TypeScript(strict) | Schema 驱动架构强依赖类型约束 |
| 构建 | Vite 6 | 秒级 HMR,开发体验好 |
| 状态 | Pinia(setup store) | 编辑器状态(页面 Schema/选中/历史)与页面列表状态分仓 |
| UI 库 | Element Plus(全量引入) | 表单类组件齐全;M1 可优化为按需引入 |
| 拖拽 | 原生 HTML5 Drag & Drop | 零依赖,满足纵向插入/排序;复杂场景再引入 dnd 库 |
| 持久化 | localStorage | MVP 无后端;通过 store 隔离,替换成本低 |

  end

    REG[物料注册表 materialMap] --- M1[文本/图片/轮播…] 
  end
  subgraph Store[状态层 stores]

  end

**关键原则:编辑与预览同源。** 画布中的组件和预览页组件来自同一物料注册表、同一份 Schema,保证所见即所得,且物料只需实现一次。

## 7. 核心设计

### 7.1 页面数据模型

```jsonc
{
  "schemaVersion": 1,          // 版本号,升级时做迁移
  "id": "p_lx8f2a9c001",
  "name": "示例首页",           // 后台管理用名称
  "title": "新品首发",          // 浏览器/分享标题
  "backgroundColor": "#f5f6f8",
  "components": [
    {
      "id": "c_lx8f2a9c002",
      "type": "carousel",      // 对应物料描述符的 type
      "props": {                // 物料自定义属性,必须 JSON 可序列化
        "images": [{ "url": "/sample-images/banner-1.svg" }],
        "height": 160,
        "autoplay": true
      }
    }
  ]
}
```

约束:Schema 是渲染唯一数据源;所有 `props` 必须可 `JSON.stringify`(函数/类实例/DOM 引用禁止入 Schema)。组件为**一维有序数组**(移动端页面从上到下流式布局,无嵌套),复杂容器类物料(如选项卡)在物料内部自管理子结构。

### 7.2 物料体系

每个物料 = `MaterialDefinition` 描述符 + 一个 Vue 组件:

```ts
interface MaterialDefinition {
  type: string            // 唯一标识,kebab-case,如 'magic-grid'
  name: string            // 展示名
  group: string           // 分组:基础组件 / 营销组件
  icon: string            // Element Plus 图标名
  description?: string
  component: Component    // 渲染组件(markRaw 包裹)
  defaultProps: () => Record<string, unknown>
  propsSchema: PropField[] // 驱动右侧属性表单
}
```

新增物料只需:建目录 `modules/materials/<type>/` → 写 `Widget.vue` + `index.ts`(描述符)→ 在 `materials/index.ts` 注册。属性面板、物料面板、图层、画布全部自动生效,**零胶水代码**。

### 7.3 渲染引擎

- `PageRenderer.vue`:接收 `PageSchema`,遍历 components,`<component :is>` 渲染,预览页使用;
- `CanvasArea.vue` + `EditableWrapper.vue`:编辑态在渲染外层包一层包装器,负责选中态、悬浮工具条、拖拽、组件名标签,不侵入物料本身。

### 7.4 属性面板 Schema 化

`PropField` 联合类型(input/textarea/number/switch/select/color/slider/image/list)描述每个属性,`FieldRenderer.vue` 负责映射为 Element Plus 表单控件并回写 store。`list` 类型支持子字段、增删、上下移(满足轮播图多图、商品多条等场景)。

### 7.5 撤销/重做

快照式:每次变更前深拷贝当前 Schema 压入 past 栈(上限 50),redo 栈对称。连续 600ms 内同 tag 的编辑(如输入框逐字符)合并为一步。深拷贝用 `JSON.parse(JSON.stringify())`(Schema 已约束可序列化,性能足够)。

### 7.6 持久化

- localStorage key:`visio:pages:v1`(页面记录数组,含完整 Schema)
- 编辑器内容变更 600ms 防抖自动落盘,离开编辑器前强制落盘
- key 带版本号,升级时写迁移函数
- M2 替换为后端 API 时,仅需改造 `stores/pages.ts` 一个文件

## 8. 关键交互设计

| 交互 | 实现 |
| --- | --- |
| 物料入画布 | 面板项 HTML5 拖拽(dragstart 写入 store + dataTransfer),画布 dragover 计算插入下标并显示指示线,drop 时插入 |
| 组件排序 | 画布内组件可拖拽,同一套插入计算逻辑 |
| 选中 | 点击组件选中(stopPropagation),点击画布空白处选中"页面"(右侧显示页面设置) |
| 快捷键 | Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z / Ctrl+Y 重做、Ctrl/Cmd+D 复制选中组件、Ctrl/Cmd+S 保存、Alt+↑/↓ 微调组件顺序、Delete 删除选中组件、Esc 取消选中(输入框聚焦时屏蔽) |
| 预览 | `/preview/:id` 新标签页打开,手机壳模拟 |

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Schema 结构升级导致旧页面打不开 | `schemaVersion` + 迁移函数;渲染遇到未知 type 时降级占位不崩溃 |
| 组件数量大时画布卡顿 | 快照深拷贝仅在变更时发生;后续可换 immer/增量 diff |
| localStorage 容量限制(~5MB) | 单页 Schema 极小(KB 级);M2 上云彻底解决 |
| 无后端导致跨设备无法共享 | 导出/导入 JSON 兜底;发布能力在 M2 提供 |
| 多标签页同时编辑互相覆盖 | 已通过 storage 事件同步列表缩小窗口;根治需 M2 后端乐观锁 |
