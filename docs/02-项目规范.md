# 项目规范(Visio 装修平台)

> 所有协作与代码合入以本文档为准;修改规范需先更新本文档。

## 1. 工程约定

- Node.js **≥ 20**(推荐 22/23),包管理器 npm
- 依赖变更必须通过 `package.json` 提交,禁止提交 `node_modules`
- 分支规范(接入 Git 后):`main`(可发布)/ `feat-<功能>` / `fix-<问题>` / `chore-<杂项>`
- 提交信息遵循 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/):
  `feat` 新功能 / `fix` 修复 / `docs` 文档 / `style` 格式 / `refactor` 重构 / `test` 测试 / `chore` 构建

```bash
git commit -m "feat(materials): 新增倒计时物料 countdown"
```

## 2. 目录结构

```
edit-visio-zcode/
├── docs/                     # 方案与规范文档(编号命名)
├── public/sample-images/     # 本地示例素材(SVG)
└── src/
    ├── main.ts               # 应用入口
    ├── App.vue               # 根组件(仅 router-view)
    ├── router/index.ts       # 路由(/、/editor/:id、/preview/:id)
    ├── styles/               # 全局样式(variables.css / base.css)
    ├── shared/               # 与 UI 无关的共享层
    │   ├── types.ts          # 全局核心类型(Schema/物料/表单字段)
    │   ├── constants.ts      # 常量(版本号、存储键、示例素材)
    │   ├── page.ts           # 页面 Schema 工厂(空白页/示例模板)
    │   └── utils/            # 纯函数工具(一个用途一个文件)
    ├── stores/               # Pinia 仓库(一个领域一个文件)
    │   ├── pages.ts          # 页面列表 CRUD + localStorage
    │   └── editor.ts         # 编辑器状态:Schema/选中/拖拽/历史
    └── modules/              # 按业务域划分的功能模块
        ├── home/             # 页面管理列表
        ├── editor/           # 编辑器(三栏布局 + components/)
        ├── preview/          # 预览页
        ├── renderer/         # 渲染引擎(PageRenderer,编辑/预览共用)
        └── materials/        # 物料层
            ├── index.ts      # 注册表(唯一需要改动的汇总文件)
            └── <type>/       # 每个物料一个目录,目录名 = 物料 type
                ├── index.ts  # MaterialDefinition 描述符
                └── XxxWidget.vue
```

**分层依赖方向**:`modules → stores → shared`,`modules/materials → shared`。禁止反向依赖(shared 不得 import modules/stores)、禁止 stores 之间循环依赖。目前唯一例外:`shared/page.ts` 引用物料注册表生成示例模板。

## 3. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 目录 | kebab-case | `magic-grid/`、`notice-bar/` |
| Vue 组件文件 | PascalCase | `MaterialPalette.vue`、`CarouselWidget.vue` |
| 物料 type | kebab-case 字符串 | `'notice-bar'` |
| TS 模块文件 | camel-case 或 index.ts | `download.ts`、`editor.ts` |
| 变量/函数 | camelCase | `dropIndex`、`moveComponentUp` |
| 类型/接口 | PascalCase | `PageSchema`、`MaterialDefinition` |
| 常量 | UPPER_SNAKE | `SCHEMA_VERSION`、`STORAGE_KEYS` |
| localStorage 键 | `visio:<域>:v<版本>` | `visio:pages:v1` |
| CSS 变量 | `--visio-*` 前缀 | `--visio-color-primary` |
| 路由 name | camelCase | `editor`、`preview` |

## 4. 代码风格

- Prettier 统一格式:单引号、无分号、行宽 100、尾逗号 all;保存即格式化(见 `.vscode/settings.json`)
- ESLint(flat config):`eslint-plugin-vue` essential + `typescript-eslint` recommended;提交前跑 `npm run lint`
- 缩进 2 空格、UTF-8、LF(见 `.editorconfig`)
- 脚本命令:`dev` / `build`(含类型检查)/ `typecheck` / `lint` / `lint:fix` / `format` / `preview`

## 5. TypeScript 规范

- `strict: true` 全开,禁止隐式 `any`;确需宽类型时写明 `unknown` 并在使用处收窄
- 纯类型导入使用 `import type`,满足 `isolatedModules`
- 核心领域类型(PageSchema/MaterialDefinition/PropField)统一定义在 `shared/types.ts`;组件私有类型(props 接口、局部类型)就近声明在组件内
- 工具函数显式标注入参出参;禁止 `@ts-ignore`(用 `@ts-expect-error` + 注释说明)

## 6. Vue 规范

- 一律 `<script setup lang="ts">` + 组合式 API
- SFC 区块顺序:`<script setup>` → `<template>` → `<style scoped>`
- props 使用类型化声明 + `withDefaults`;组件内部不直接修改 props,通过 emit 或 store 回写
- 组件命名多单词(Widget/Panel/View 后缀);物料渲染组件统一 `XxxWidget`
- 禁止 `v-html`(安全);列表渲染必须提供 `key`
- 通用 UI 用 Element Plus(`size="small"` 为主),图标来自 `@element-plus/icons-vue`

## 7. 样式规范

- 组件样式一律 `scoped`;全局仅 `styles/` 两个文件
- 设计变量集中在 `styles/variables.css`(`--visio-*` 前缀),禁止硬编码重复色值
- 画布以 **375px 设计稿**为基准,物料内使用 px;手机端视觉还原优先
- 类名语义化(BEM 可选),禁止 Id 选择器与 `!important`

## 8. 数据与存储规范

- **Schema 中只允许存放 JSON 可序列化的值**(string/number/boolean/null/数组/对象);禁止函数、类实例、响应式代理引用
- 深拷贝统一使用 `shared/utils/clone.ts` 的 `deepClone`
- 结构升级必须递增 `shared/constants.ts` 的 `SCHEMA_VERSION` 并提供迁移函数
- localStorage 访问只允许出现在 `stores/pages.ts`,其余模块通过 store 读写

## 9. 物料开发规范(SOP)

新增一个物料的完整步骤(以 `countdown` 倒计时为例):

1. 建目录 `src/modules/materials/countdown/`
2. 实现 `CountdownWidget.vue`:
   - props 全部可选并提供默认值(画布直接 `v-bind="props"` 渲染,缺省必须可看)
   - 空数据显示占位(如"请配置 xx"),不允许空白/报错
   - 图片加 `draggable="false"` 防止干扰画布拖拽
3. 编写 `index.ts` 描述符:`type/name/group/icon/description/component(markRaw)/defaultProps/propsSchema`
4. 在 `materials/index.ts` 的 `materialList` 中注册
5. 自检清单:
   - [ ] 从物料面板拖入/点击添加,画布正常渲染
   - [ ] 右侧属性逐项修改,画布实时生效
   - [ ] 删除必填数据(如清空图片)显示占位而非崩溃
   - [ ] 预览页显示正常
   - [ ] `npm run typecheck && npm run lint` 通过

描述符骨架:

```ts
export const countdownMaterial: MaterialDefinition = {
  type: 'countdown',
  name: '倒计时',
  group: '营销组件',
  icon: 'AlarmClock',
  description: '活动倒计时',
  component: markRaw(CountdownWidget),
  defaultProps: () => ({ endTime: '', color: '#ff4d4f' }),
  propsSchema: [
    { type: 'input', key: 'endTime', label: '结束时间' },
    { type: 'color', key: 'color', label: '文字颜色' },
  ],
}
```

## 10. 编辑器行为规范

- 任何会修改 Schema 的操作必须先 `pushHistory(tag)`,tag 格式 `动作:id:key`
- 组件 id 一律通过 `createId('c')` 生成,页面 id 前缀 `p`
- 交互类全局副作用(快捷键监听、自动保存)随组件生命周期成对注册/销毁
- 不确定组件 type 是否存在时使用 `getMaterial(type)` 判空降级,不允许假设一定存在

## 11. 测试规范

- 测试框架 Vitest,命令 `npm run test`(CI)/ `npm run test:watch`(开发)
- 测试文件与被测对象同目录,放在 `__tests__/` 下,命名 `<模块>.spec.ts`
- 优先覆盖:纯工具函数、store 行为(历史、持久化、边界)、Schema 工厂
- store 测试中用 `vi.mock('@/modules/materials', …)` 隔离 .vue 组件(node 环境无 DOM);需要 localStorage 时用 `vi.stubGlobal('localStorage', …)` 注入内存实现
- 时间相关逻辑(防抖、历史合并窗口)用 `vi.useFakeTimers()` + `vi.setSystemTime()` 控制
- 提交前保证 `npm run test && npm run typecheck && npm run lint` 全绿

## 12. 文档规范

- `docs/` 下文档按 `序号-主题.md` 命名,新增功能如涉及方案变更需同步更新 `01-总体方案.md`
- README 保持"5 分钟可上手":简介、快速开始、脚本、目录、文档索引
