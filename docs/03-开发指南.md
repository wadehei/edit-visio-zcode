# 03 · 开发指南(新人上手)

> 目标:新接手的同学 10 分钟内跑起来项目、30 分钟内能独立加一个物料。规范细节见 [02-项目规范](02-项目规范.md)。

## 1. 环境准备

- Node.js ≥ 20(用 `node -v` 确认)
- 首次:`npm install`(会自动安装 git pre-commit 钩子,见 §5)

```bash
npm run dev     # 开发服务器。5173 被占用时 Vite 自动换 5174,以终端输出为准
```

## 2. 常用命令

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 开发服务器(HMR) |
| `npm run check` | **一键质量门**:test + typecheck + lint(提交前必跑,pre-commit 自动执行) |
| `npm run test` / `test:watch` | Vitest 单元测试 |
| `npm run build` | 类型检查 + 生产构建 |
| `npm run lint:fix` / `format` | ESLint 修复 / Prettier 格式化 |

## 3. 架构分层(依赖方向自上而下)

```
shared/    类型(types.ts)、常量(constants.ts)、纯工具函数、Schema 工厂(page.ts)
  ↑
stores/    Pinia:pages(页面列表,localStorage 唯一访问点)、editor(编辑态/历史/剪贴板)、templates
  ↑
modules/
  ├── materials/   物料注册表(每个物料一个目录:Widget.vue + index.ts)
  ├── renderer/    PageRenderer:Schema → 界面,编辑/预览/首页缩略图共用
  ├── editor/      三栏编辑器(CanvasArea / MaterialPalette / PropsPanel + 弹窗组件)
  ├── home/        页面管理列表
  └── preview/     预览页
```

要点:

- **数据流单向**:`PageSchema(纯 JSON)` 是渲染唯一数据源;编辑操作都走 editor store 的 action(自动记历史),组件内不要直接改 `props.comp.props`。
- **localStorage 只在 `stores/` 各 store 内读写**(键集中在 `shared/constants.ts` 的 `STORAGE_KEYS`),加载/损坏备份统一走 `shared/utils/storage.ts` 的 `loadJsonCollection`/`backupCorrupted`,不要在 store 里手写容错;后续接后端只需改造各 store 的加载与 persist。
- **历史快照**:editor store 用 `{label, snapshot}` 数组存撤销;`pushHistory(tag)` 的 tag 决定合并行为——`prop:`/`page:` 开头的 600ms 内合并为一步,其余每次都是一步。新增 action 记得先 `pushHistory` 再改数据。

## 4. 新增一个物料(5 步 SOP)

以「倒计时」为例:

1. 建目录 `src/modules/materials/countdown/`,写渲染组件 `CountdownWidget.vue`——**只读 `props` 渲染,不写 props**(预览/编辑共用同一组件)。
2. 同目录建 `index.ts`,导出 `MaterialDefinition`:

   ```ts
   import { markRaw } from 'vue'
   import type { MaterialDefinition } from '@/shared/types'
   import CountdownWidget from './CountdownWidget.vue'

   export default {
     type: 'countdown',            // kebab-case,与目录名一致
     name: '倒计时',
     group: '营销组件',
     icon: 'Timer',                // Element Plus 图标名(字符串,动态解析)
     component: markRaw(CountdownWidget),
     defaultProps: () => ({ endTime: '2026-12-31 23:59:59' }),
     propsSchema: [{ type: 'input', key: 'endTime', label: '截止时间' }],
   } satisfies MaterialDefinition
   ```

3. 在 `src/modules/materials/index.ts` 注册(数组加一行)。物料面板/命令面板/画布自动生效。
4. 可选增强:
   - **跳转链接**:`defaultProps` 加 `link`,渲染层用 `window.open`(参考 button 物料)。
   - **换肤适配**:`stores/editor.ts` 的 `applyTheme` switch 加分支。
   - **体检规则**:`modules/editor/doctor.ts` 加 case(占位内容、空列表等)。
5. 补测试:props 工厂、doctor 规则(如有)各加一条用例,`npm run check` 全绿。

## 5. 工程化约定

- **pre-commit 质量门**:`simple-git-hooks` 在每次 `git commit` 前自动跑 `npm run check`(约 10-20s)。急提交可 `git commit --no-verify` 跳过,但 CI/协作前务必补跑。
- **Element Plus 按需引入**:模板里直接写 `el-*`,由 `unplugin-vue-components` 自动注入(vite.config.ts)。注意两点:
  - 命令式 API(`ElMessage`/`ElMessageBox`)手动 import 的,**样式要在 `main.ts` 手动引** `element-plus/es/components/<name>/style/css`;
  - `vite.config.ts` 的 `manualChunks` **不要列 element-plus**,否则整包打包、按需失效(曾导致 1MB chunk)。
- **`src/components.d.ts`** 是 unplugin 自动生成的类型声明,已提交,不要手改;新组件报"未注册"时重启 dev server。

## 6. 常见坑(Windows 环境实测)

| 现象 | 处理 |
| --- | --- |
| 改了文件页面没更新 | Vite 偶发漏变更事件:`touch <文件>` 或重启 dev server |
| `.vue` 的 style 改动 curl 验证不到 | 样式走独立模块,请求 `?vue&type=style` 变体 |
| 5173 端口被占 | 本机常有其他项目占 5173,Vite 自动落到 5174,看启动日志 |
| el-tabs 初始不激活 | Element Plus 已知行为,面板 tab 用自绘按钮(见 MaterialPalette) |
| 画布缩放后点击错位 | 画布用 CSS `zoom`(非 transform),Chrome/FF126+ 布局参与,坐标天然一致;勿改成 transform |

## 7. 测试怎么写

- 位置:与被测文件同目录 `__tests__/*.spec.ts`。
- store 测试:先 `vi.mock('@/modules/materials')`(物料含 .vue,node 环境隔离),`vi.stubGlobal('localStorage', createLocalStorageStub())`(共享 stub 在 `src/stores/__tests__/storage-stub.ts`)。
- 断言偏好:测行为结果(组件数、快照标签、localStorage 内容),不测内部实现。
- 跑法:`npm run test`(全量)或 `npx vitest run src/stores`(单目录)。

## 8. 提交前自查清单

1. `npm run check` 全绿(45+ 用例、类型、lint)。
2. 新功能有对应测试;修 bug 先补一个能复现的用例。
3. 涉及 Schema 变更(新字段)时确认旧数据兼容(字段可选、加载侧过滤脏数据)。
4. UI 改动在浏览器过一遍首页 + 编辑器 + 预览三条链路。
